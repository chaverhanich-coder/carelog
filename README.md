# Rabbi's Care Log

Live app: https://als-aide-care-log.pally.site

Link-based care log for Rabbi's aides: vitals and blood-pressure photo logs, medication check-offs, a routine schedule with appointments, an all-logs view, backup and export, and an offline copy on each phone that syncs to a shared database when online. Anyone with the link can read and write. It is an unvalidated prototype and must not be used for medication decisions.

## What is in this repo

- `app/` - copy of the code that runs the live app, taken from the page on 25 Nov 2026.
  - `app/config.js` - page title, description and visitor access
  - `app/design-tokens.js` - colors, fonts, spacing
  - `app/styles.css` - the app's CSS
  - `app/server.js` - database schema, sync operations, photo storage, wipe, API routes
  - `app/render.js` - the HTML shell with the Schedule, Home and Settings tabs
  - `app/client.js` - the browser app: log, schedule, settings, offline store and sync
- `index.html` - an earlier standalone version of the log. It runs on its own with no server and keeps entries in that browser only. It is not the app that is live now.
- `android-shell/` - Android WebView wrapper that opens the live page full screen.
- `dist/rabbis-care-log.apk` - built APK from that wrapper.
- `.github/workflows/build-apk.yml` - builds the APK on push.

## How the live app runs

The page is a Cloudflare Worker backed by a D1 (SQLite) database. The worker serves the HTML from `render.js` with the CSS and `client.js` inlined, and handles:

- `GET /api/state` - full current state
- `POST /api/sync` - batches of operations from a phone (log put, undo, retake; item put and delete with revision checks)
- `GET /api/epoch` and `POST /api/wipe` - shared-data wipe with an epoch bump
- `POST /api/photos/:id` and `GET /api/photos/:id` - JPEG photo storage
- `GET /sw.js` and `GET /manifest.webmanifest` - offline shell and install

Tables: `rd_items` (routines, medications, appointments), `rd_logs` (log rows with an optional occurrence key, so two phones cannot both log the same slot), `rd_photos`, plus the older `care_entries` and `care_meds` kept for the legacy entries and migrated once.

Each phone keeps an IndexedDB copy (`rabbi-day`) with its own queue and pushes unsent changes when it is online.

The Schedule, Home and Settings tabs: Home is the middle and default tab, opens onto the live clock card with today's log under it, and only the clock updates every second. Logs load 40 rows at a time and the upcoming schedule 7 days at a time.

## What this copy does not include

Pally's shared page runtime that wraps the app: the locale string catalogue, the page router and owner door, the RSVP and calendar invitation helpers, and the base CSS. Those are generated by the hosting and are not part of this app. `app/` is a full copy of the app's own code, not a build that runs by itself: it needs the page's database and secret from the hosting.
